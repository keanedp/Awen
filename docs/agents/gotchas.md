# Gotchas

Traps already hit in this repo. Add new ones as you find them, and remove any that stop being true.

## Machine / shell
- `sed` is GNU sed: use `sed -i`, not `sed -i ''`.
- `grep` is ugrep, so some regex syntax differs from GNU grep. For example, `(\.|--|...)` alternations failed.
- **Line-ending fixtures need explicit Git attributes.** Windows with `core.autocrlf=true` otherwise checks `test_docs/lf.md` out as CRLF, making W-052's manual LF/CRLF verification meaningless. Keep the `eol=lf` / `eol=crlf` rules in `.gitattributes`.
- There is no `rustup` (Rust comes from Homebrew), so there are no cross targets. `#[cfg(windows)]` code **cannot be compiled here**. Write it against the crate sources; CI's Windows job (`ci.yml`) is where it gets compiled and linted, so push a branch to check it. Running it on real Windows is still unverified.
- **macOS-only helpers fail Windows CI as dead code.** CI runs clippy with `-D warnings`, so a function, type or field used only from `#[cfg(target_os = "macos")]` code breaks the Windows job. Put the same `cfg` on a function that only macOS calls. For a type that the cross-platform stubs still name, add `#[cfg_attr(not(target_os = "macos"), allow(dead_code))]` (see `export::Format`, `rename::Anchor`).
- **Never run a bare `cargo fetch`.** It downloads and unpacks dependencies for every platform, including the huge `windows` crates, and once filled the disk (every command then fails with ENOSPC). To read one crate's source, download just that `.crate` from `https://static.crates.io/crates/<name>/<name>-<ver>.crate` into a scratch directory.

## Build / bundle
- **DMG bundling fails** with `error running bundle_dmg.sh`. The cause is a Awen launched from the temporary `/Volumes/dmg.*` mount during a previous build, which blocks the eject. Fix: quit that app, `hdiutil detach -force /Volumes/dmg.*`, delete `src-tauri/target/release/bundle/macos/rw.*.dmg`, and rebuild. Don't open the app from the Finder window that pops up during `make build`.
- `src-tauri/gen/schemas/` is regenerated every build, so don't edit or commit it.
- **A new draft release can be missing from the releases list for a moment**, and its URL is `untagged-…` until it's published. Looking it up by tag straight after `gh release create` returned nothing, so the builds got no release to upload to. `release.yml` checks the create call's result instead, and the builds find the draft by tag minutes later.
- **MSI limits the version.** WiX rejects a non-numeric pre-release (`0.2.0-beta.1`), and major/minor above 255. Use `0.2.0-1`. `scripts/version.mjs` refuses anything else, so the Windows build doesn't fail at the end of a release.

## Frontend
- `@hedgedoc/markdown-it-task-lists` crashes with markdown-it 14 (`ERR_PACKAGE_PATH_NOT_EXPORTED` for `markdown-it/lib/token.js`). Use `markdown-it-task-lists`, whose types come from the local `src/lib/preview/markdown-it-task-lists.d.ts`.
- In Vitest, importing a `.css` file gives an empty string, even with `?raw`, so tests can't read `app.css` (`html.test.ts` only checks the export's own CSS).
- **Monaspace's variable files default to weight 200 (ExtraLight).** An `@font-face` without `font-weight: 200 800` renders body text that thin. The same goes for `font-style: oblique 0deg 11deg`, which italic needs.
- CSS custom properties can't take a fallback list like a font stack: `--accent: -apple-system-control-accent, #0a84ff` is invalid. Use a single value (or `var(--x, fallback)`).
- **`-apple-system-control-accent` is always blue in a Tauri WKWebView.** It only follows System Settings when WebKit's private system-appearance mode is on. WebView2 has no CSS for the Windows accent at all. So `src-tauri/src/accent.rs` reads it natively and `applyAccent()` sets `--system-accent` / `--system-accent-dark`, which the token files use.
- **Testing a module outside the app:** `ssrLoadModule` resolves `$lib` and `?raw` imports, but it runs in SvelteKit's dev server, which replaces the global `fetch` and rejects relative URLs. Stub `fetch` *after* `createServer()`.
- **Never style scrollbars on macOS.** Any `::-webkit-scrollbar` rule makes WKWebView swap native overlay scrollbars (hidden until you scroll or hover) for legacy always-visible ones. The mac token file intentionally has none. The Windows token file does style them.
- **Document positions vs. strings in CRLF files.** CodeMirror counts every line break as one position, but `state.sliceDoc()` and `documentText()` join lines with the file's separator, which is two characters in a CRLF file. Indexing that string by document positions drifts by one character per line. When mapping positions onto text (as `count.ts` does), use `state.doc.sliceString(from, to, "\n")`. Tests of such code should use a CRLF `createState`.
- **Tests run in V8, the macOS app runs JavaScriptCore.** Vitest uses Node (V8, like WebView2), but WKWebView uses the system JavaScriptCore, and built-ins can differ. Found so far: JSC's `Intl.Segmenter` reports numbers as `isWordLike: false`, so a word count based on it skipped "2" (`count.ts` checks for a letter or digit instead). When code depends on `Intl`, regexes with Unicode properties or other built-ins, check it in JSC without launching the app: `osascript -l JavaScript -e '<code>'` runs the system JavaScriptCore.
- **Lezer `tree.iterate` enters nested trees by default.** With editor code highlighting on (W-045), fenced code is a mounted JS/CSS/… tree whose node names (`Comment`, `String`, `HeaderMark` in a ```` ```md ```` block) collide with Markdown's. Code that walks the Markdown tree by node name must pass `mode: IterMode.IgnoreMounts`, as `count.ts` and `markdownStyling.ts` do.
- **WebKit's spelling marks don't survive CodeMirror redraws.** They live on text nodes, which CodeMirror rewrites when it redraws a line, and WebKit only rechecks the word just typed. So `spellcheck="true"` on the editor loses marks as you type. Spelling is the editor's own (`editor/spelling.ts`); don't turn WebKit's back on.
- **WKWebView leaves a stale native caret when the DOM under it is replaced.** When CodeMirror rebuilds the caret's line (its syntax styling changed, e.g. deleting a fence's backticks), WebKit draws the new caret but doesn't erase the old one. Re-setting the selection doesn't clear it. The editor uses `drawSelection()` for this; don't remove it without checking fence editing.
- **Don't set classes or styles on CodeMirror's own elements by hand.** It rewrites `.cm-editor`'s `class` attribute on every focus change, wiping added classes. And it doesn't notice layout you change behind its back, so it doesn't re-measure: drawn carets and selections stay where the text used to be. Typewriter scrolling (W-018) did both at first, and turning it off left the caret drawn mid-screen. Use `EditorView.editorAttributes` / `contentAttributes` (from a `StateField` if the value is measured), so the change happens inside CodeMirror's update.
- **CodeMirror's scroll anchoring ignores `.cm-content` padding.** It keeps line positions in its height map, which starts below the padding, so when padding changes the text on screen jumps by the difference. `view.scrollSnapshot()` has the same blind spot. To keep text still across a padding change, note the line's screen position first, then in a `requestMeasure` after the change scroll by however far it actually moved (see `setTypewriterScrolling`). An absolute `scrollIntoView` target worked out beforehand is fragile when something else also moves the scroll.
- **WebKit moves the scroll position when CodeMirror rewraps many lines at once.** Turning focus mode on or off wraps (or unwraps) nearly every visible line in a mark, and WKWebView's `scrollTop` drops by hundreds of pixels during that DOM sync, with the same scroll height and no script scrolling. Chrome keeps it. `setFocusMode` saves `scrollTop` and puts it back after the dispatch. Suspect the same for any new decoration that marks most of the document at once.
- **Check scroll and layout bugs in WebKit, not Chrome.** Chrome didn't reproduce the focus mode jump above. To test editor behavior without launching the app: bundle the editor modules with esbuild (`--loader:.svelte=empty`, `--charset=utf8`) into a page, serve it on 127.0.0.1, and load it in a WKWebView from a small `swiftc`-built AppKit program that runs a script with `callAsyncJavaScript` and prints the result. The window must be on screen (an off-screen or hidden one gets no `requestAnimationFrame`, so CodeMirror never measures); `alphaValue = 0.01` keeps it invisible. Headless Chrome over the DevTools protocol works for engine-independent checks; with `--virtual-time-budget` it never fires `requestAnimationFrame` either.
- Svelte 5's `mount()` doesn't run effects synchronously, and `bind:this` is an effect. A component mounted imperatively (the find bar) needs `flushSync()` before its element refs exist.
- Accessibility warnings from svelte-check: prefer a document-level listener (e.g. the `.chrome` context-menu blocker) over handlers on non-interactive elements.

## Tauri / native
- `tauri.<platform>.conf.json` is merged with JSON Merge Patch, so **arrays are replaced, not merged**. `tauri.windows.conf.json` must repeat the whole `app.windows[0]` object, not just the changed key. Keep both files' window settings in step.
- **Windows document windows must also start with `visible: false`.** The platform override replaces the base window array, so omitting it exposes the unstyled white web view and menu during dark-mode startup. The page shows the window after applying platform styles; later document windows clone the same configuration.
- `data-tauri-drag-region` only starts a drag when the clicked element itself carries the attribute. Buttons inside the title bar are therefore not drag handles, but any text or icon *wrappers* that should drag need the attribute too, or `pointer-events: none`, as the title text has.
- The `.menu(...)` builder runs before Tauri manages its `PathResolver`, so calling `app.path()` there panics with `state() called before manage()`. Do path-dependent work in `.setup(...)`, as `recent::load` does.
- `Menu::get(id)` only searches top-level items. To reach a nested item later (e.g. the View → Preview checkmark), keep its handle in managed state (`menu::CheckItems`).
- Windows custom title bar: HTML caption buttons don't trigger the Snap Layouts flyout (W-037). Win+Z and dragging to screen edges still work.
- **`decorations: false` hides the native menu bar on Windows.** Tauri still attaches the app menu to the window, but the Win32 menu bar lives in the non-client area, which an undecorated window doesn't have. So the menu is there but never drawn. Document windows now take it off (`hide_menu`), and `MenuBar.svelte` + `menubar.rs` draw and run one instead (W-073). `hide_menu` only unsets the Win32 menu: muda's window subclass stays, so `WM_COMMAND`s still become menu events, and Tauri's accelerator hook doesn't depend on it either.
- **`TrackPopupMenu` is modal and knows only its own menu.** It captures the mouse, so the web view sees no hover or clicks while a popup is open. Switching menus needs a `WH_MSGFILTER` hook (`MSGF_MENU`) that ends the popup (`EndMenu`) and opens the neighbor, as `menubar.rs` does.
- **Tauri accelerators name physical keys, not characters.** `"CmdOrCtrl+Shift+."` shows as ⇧⌘. and there's no way to write ⌘>. muda has a character-based `KeyAccelerator`, but Tauri 2.11 doesn't expose it or the muda item. On macOS, `menu::use_character_shortcuts` sets such shortcuts on the `NSMenuItem` directly, found by its title, after the menu is built. Rename a menu item there too.
- A native menu accelerator consumes the key before the webview sees it. Any shortcut CodeMirror must handle has to be a custom menu item that calls into the editor, as undo/redo do.
  - The same custom item also fires while focus is in an `<input>`, such as the find bar. `runHistory` checks for that case and calls `document.execCommand("undo")` there, so the field's text is undone, not the document.
- **Creating a window from a synchronous command deadlocks on Windows.** Commands that may open a window (`open_document`) must be `async`. Menu and run-event handlers are fine.
- JS `listen()` from `@tauri-apps/api/event` hears events emitted to *any* target, so `emit_to` a window doesn't isolate it. Listen with `getCurrentWebviewWindow().listen(...)`.
- **File associations only exist in a bundled app.** `make dev` runs a bare binary that LaunchServices doesn't know, so testing Finder double-click / Open With needs `make build` (then run `Awen.app` from `target/release/bundle/macos/`, not from the DMG). macOS may keep an older registration: `lsregister -f <path to Awen.app>` refreshes it.
- **`RunEvent::Opened` can come before `RunEvent::Ready`** when the app is launched by opening a file: AppKit sends `application:openURLs:` before `applicationDidFinishLaunching:`, so the config windows and anything managed in `setup` don't exist yet. Queue and handle after setup (`documents::finish_launching`).
- **macOS windows with the default (Visible) title bar clip the web view's bottom.** Tauri gives them a full-size content view, and the web view sits below the title bar while keeping the content view's height, so the bottom ~28pt is off-window and a page that sizes its window to its content comes out short. The Settings window uses the Overlay style instead and pads the page under the title bar.
- Capabilities apply by window label. New windows are `doc-N`, which `capabilities/default.json` matches with `doc-*`. A window with any other label would get no permissions; Settings (`settings`) has its own `capabilities/settings.json`.
- tao's macOS app delegate has no `applicationShouldTerminate:`, so Dock Quit and logout terminate immediately unless we add it (`terminate.rs`). tao's own exit uses `NSApp stop:`, not `terminate:`, so the added handler never sees `app.exit`.
- Tauri app-defined commands need no capability entry. Plugin APIs do: add them to `src-tauri/capabilities/default.json`, e.g. `opener:default` and `dialog:default`.
- **macOS PDF export** (verified working). WKWebView print operations can render blank pages unless run with `runOperationModalForWindow…` and the print view's frame set. `export.rs` does both. If PDFs come out blank or as one long page, look here first.
- **WebView2 `PrintToPdf`** (Windows) prints with default settings, where backgrounds are off. Checked task-list boxes may lose their fill in Windows PDFs.
- **Print and PDF clip anything left of `.preview`**, because the print rules remove its padding. Outside list markers hang there, so list indents must be wider than the widest marker. WebKit draws `1. ` with a trailing space. In SF (the macOS preview font) digits are at most 0.62em, `.` 0.22em and a space 0.2em, so `10. ` is about 1.65em against a 2.5em ordered-list indent. Recheck if `--font-preview` changes. Wide tables clipped the same way: on screen they're `display: block` so they scroll, which paper can't. See "Wide tables in print" in `architecture.md`.
- **Content wider than the page shrinks the whole PDF.** macOS PDF export uses `NSPrintingPaginationMode::Fit` (and Chrome does the same), so one table that overflows the margin scales every page down. Anything in print must fit the page width, not merely be allowed to overflow it.
- **`overflow-wrap: anywhere` in a table cell splits words that would fit.** It shrinks the cell's min-content, and auto table layout squeezes such columns below their natural width first. That's why print keeps links whole unless the table can't fit at 6pt.
- **Saving a file inside the repo reloaded the dev app.** Tailwind's Vite plugin scans the whole project for class names and sends a full page reload when a scanned non-code file changes, so saving e.g. `test_files/lf.md` during `make dev` reset every window to a blank Untitled document. `app.css` now limits scanning to `src/` (`source("../")`). Release builds were never affected. Keep test documents outside `src/`.
- **The updater can't replace an app opened from its disk image.** macOS runs a quarantined app opened from a downloaded DMG from a random read-only "AppTranslocation" mount, and the DMG itself is read-only, so installing failed with "Read-only file system (os error 30)" after the download. `updates::read_only_app` (`statfs`, `MNT_RDONLY`) now catches it first and asks the user to move Awen to Applications. To see where a running copy lives: `ps -axo command | grep Awen.app`.
- **A web view is white until its page is styled, even in dark mode.** Tauri's `background_color` would fix it, but on macOS it only reaches the web view with `macOSPrivateApi` (wry's `transparent` feature), which blocks the Mac App Store. So windows open hidden and the page shows them (see Document windows in `architecture.md`). A page opened hidden must call `show()` and needs `core:window:allow-show`, or its window never appears. Don't wait for `requestAnimationFrame` first: a hidden WKWebView never fires it.
